# Project Demonstration Guide

## 1. Purpose

This guide provides a reliable sequence for demonstrating the AI-Powered Cyber Defense Simulator during a project review, presentation, interview, or evaluation.

The demonstration shows:

- Dynamic security-event generation
- Rule-based attack detection
- Isolation Forest anomaly detection
- Alert correlation
- Multi-agent incident analysis
- Response decisions
- Safety and approval controls
- Simulated defensive actions
- Database persistence
- FastAPI endpoints
- React dashboard visualization

## 2. Before the Demonstration

Open PowerShell in the project folder:

```powershell
cd "D:\Projects\AI Cyber Defense Simulator"
```

Activate the Python environment:

```powershell
.\venv\Scripts\Activate.ps1
```

Confirm that the trained model exists:

```powershell
Test-Path models\isolation_forest.joblib
```

```text
True
```

## 7. Expected Demonstration Sequence

Demo mode produces normal activity between the following attacks:

1. Distributed brute force
2. DDoS
3. Port scan
4. Suspicious process activity

The exact IP addresses, usernames, endpoints, ports, and process identifiers are generated by the scenario engine.

## 8. Distributed Brute-Force Demonstration

The simulator generates failed login attempts against one user account from multiple attacker IP addresses.

Expected detection:

```text
Incident Type: DISTRIBUTED_BRUTE_FORCE
Detection Method: RULE_BASED
Decision: BLOCK_IPS
```

The incident may later receive supporting evidence from Isolation Forest.

Expected safety behaviour:

```text
Response Status: APPROVAL_REQUIRED
```

Blocking multiple IP addresses is considered a high-impact action and requires approval.

Only IP addresses confirmed by the matching rule-based alert are selected as response targets.

## 9. DDoS Demonstration

The simulator generates many HTTP requests from several attacker IPs against one endpoint.

Expected detection:

```text
Incident Type: DDOS
Decision: RATE_LIMIT_IPS
```

Expected response:

```text
Response Status: SIMULATED_SUCCESS
Automatic: True
```

If the same incident produces another correlated update, the repeated response may show:

```text
Response Status: SUPPRESSED_DUPLICATE
```

This proves that the safety layer prevents the same containment action from being repeatedly executed.

## 10. Port-Scan Demonstration

The simulator generates connections from one scanner IP to several destination ports on one target system.

Expected detection:

```text
Incident Type: PORT_SCAN
Decision: BLOCK_IP
```

Expected response:

```text
Response Status: SIMULATED_SUCCESS
Automatic: True
```

The scanner IP should appear as the response target.

## 11. Suspicious-Process Demonstration

The simulator generates process activity using indicators such as:

- Suspicious parent applications
- Temporary executable locations
- Encoded commands
- Download-related commands

Expected detection:

```text
Incident Type: SUSPICIOUS_PROCESS
Decision: QUARANTINE_PROCESS
```

Expected safety behaviour:

```text
Response Status: APPROVAL_REQUIRED
```

Process quarantine requires approval because terminating or isolating the wrong process could affect the system.

The action is simulated and no real process is terminated.

## 12. AI Anomaly Detection

Events are collected into configured time windows.

Isolation Forest extracts numerical features from each completed window and determines whether the activity differs from learned normal behaviour.

When unusual behaviour is found, it generates:

```text
Attack Type: ANOMALOUS_BEHAVIOR
Detection Method: ISOLATION_FOREST
```

AI-only anomalies normally produce:

```text
Decision: FLAG_FOR_INVESTIGATION
Automatic: False
```

This is intentional. The model identifies unusual behaviour but may not know the exact attack type.

## 15. Evaluation Demonstration

Run:

Explain the final hybrid detection results:

| Method | Accuracy | Detection Rate | False Positive Rate |
|---|---:|---:|---:|
| Rule-based | 71.4% | 66.7% | 0.0% |
| Isolation Forest | 75.6% | 71.8% | 2.0% |
| Hybrid | 99.7% | 100.0% | 2.0% |

Important explanation:

- Rules are precise for known attacks.
- Rules miss attacks that remain below their thresholds.
- Isolation Forest detects unusual threshold-evasion behaviour.
- The hybrid system combines both methods.
